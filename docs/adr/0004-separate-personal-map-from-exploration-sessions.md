# ADR 0004: 個人地図と探索セッションを分離する

- Status: Accepted
- Date: 2026-08-07

## Context

初期実装では、1回の `exploration` をそのまま1枚の地図として保存・表示していた。このまま探索回数が増えると、ユーザーが得るものは「育つ自分の地図」ではなく、日付ごとのGPSログ一覧になりやすい。

製品の正本は長期的に育つ個人地図であり、探索セッションはその地図を更新するための観測単位である。両者はライフサイクルも責務も異なる。

## Decision

- `PersonalMap` を長期的な集約単位とする。
- `ExplorationSession` は開始から終了までの1回の記録とraw観測を所有する。
- 1つの個人地図は1件以上の探索セッションから再生成する。
- セッションごとの経路を独立したsegmentとして保持し、セッション間を未観測の直線で接続しない。
- GNSSセッションは地理座標を介して共通のローカル座標系へ再投影する。
- GPSなしのlocalセッションは、同じ明示的frameまたはanchor transformがない限り統合しない。
- マーカーも各セッションの観測座標から個人地図のframeへ変換する。
- ホーム画面の主語は将来的に探索履歴ではなく個人地図とする。探索履歴は地図の内訳として扱う。

## Consequences

- mapping-coreは複数セッションをsegment付きの個人地図へ集約するAPIを持つ。
- SQLiteには個人地図と探索セッションの関連を追加し、既存データを移行する必要がある。
- レンダラーは単一polylineではなく複数segmentを描画する必要がある。
- 複数回の探索から地図が育つという製品仮説を、実機ドッグフードで直接評価できる。
- frameが接続できないセッションを暗黙に混ぜないため、誤った地図を生成しにくい。
