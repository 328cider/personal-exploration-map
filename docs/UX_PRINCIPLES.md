# UI / UX原則

## 1. 現実が主画面

探索中に画面を見続ける設計は失敗とみなす。開始後は「スマホはしまって大丈夫」と明示し、必要時以外の操作を求めない。

### 必須フロー

```text
Home → 探索開始 → ポケット → 必要時だけ発見 → 探索終了 → PersonalMapレビュー
```

## 2. 一回の探索で成果を出す

「同じ場所を数回通ると道になる」は採用しない。初回の受理済みサンプルから即座に経路を作る。再訪は精度、接続、探索範囲を改善する材料にする。

## 3. UIの主語は長期的なPersonalMap

1回の記録は`ExplorationSession`だが、ユーザーがHomeで管理し、Reviewで見返す主語は`PersonalMap`である。

- Homeに日付別GPSログを並べない
- 同じPersonalMapの続きを探索できる
- 複数sessionは1枚の地図へ集約する
- session間を、歩行証拠なしの直線でつながない
- 探索回数、合計経路、発見を地図の成長として示す
- session履歴は地図の内訳や診断として扱う

「新しい地図を探索する」と「この地図の続きを探索する」は明示するが、記録中の操作体系は共通にする。

## 4. モードを場所カテゴリで分けない

「山」「キャンプ」「街」「建物」の選択を開始前に要求しない。ユーザーに必要なのは `探索を始める` だけで、内部の位置プロバイダーや精度表示が環境に応じて変わる。

座標frameを安全に統合できない場合は、場所カテゴリの選択で誤魔化さず、継続を無効化して理由を示す。たとえばlocal-frame mapへGNSS sessionを明示anchorなしで追加しない。

## 5. 権限は段階的に説明する

起動直後に位置権限を連続要求しない。

1. ユーザーが探索開始を選ぶ
2. 利用中の位置権限の理由を説明して要求
3. 「ポケットに入れて画面を消しても記録する」ためにバックグラウンド権限が必要だと説明
4. 拒否された場合は、動作制限を具体的に表示する

権限拒否をエラー扱いだけにせず、前面記録・設定を開く・中止の選択肢を示す。

続きを探索する場合は、どのPersonalMapへ新しいsessionを追加するかを権限画面で明示する。場所カテゴリや内部providerは選ばせない。

## 6. 発見入力は10秒以内を目標にする

通常の記録は以下の2段階までにする。

```text
発見を記録 → 種類を1タップ → 保存
```

任意で短いメモを追加できる。写真を必須にしない。マーカー候補は少数に保ち、ユーザー定義は後から追加する。

初期候補:

- 気になる
- 入口 / 出口
- 分岐 / 接続
- 階段 / 高低差
- 危険 / 通れない
- メモ

## 7. 不確実性を地図の文法にする

誤差を隠して正確そうな線を描かない。

- 高確度: 実線・高い不透明度
- 低確度: 薄い線、幅、または警告
- 記録欠落: ギャップとして表示
- 手動入力: 観測方法を区別
- 推定構造: 事実レイヤーと分離
- session境界: 開始・終了点を別々に表示し、偽接続しない

ユーザーが「地図が間違っている」のか「測位が不確か」なのかを判断できるようにする。

## 8. 終了忘れと中断から回復する

- Androidでは継続中通知から探索画面へ戻れる
- アプリ再起動時にactive sessionとPersonalMap contextを検出する
- `app_state`が欠けてもrecording sessionから復元する
- 長時間静止時は通知で確認するが、自動終了で記録を失わない
- OSにより記録が止まった場合は、終了レビューで欠落を表示する
- tracking停止後に完了transactionが失敗した場合、recording contextを復元して再試行可能にする

## 9. 安全を損なわない

- 歩行中の画面注視を促さない
- 音や振動は最小限
- 危険な場所への立ち入りや探索率競争を促進しない
- 地図は救助・測量・安全保証用途ではないことを明示する

## 10. ゲームは任意で無効化できる

Fog、探索率、実績、収集物を使わなくても、地図アプリとして完成していること。ゲームのために記録開始や発見入力が複雑にならないこと。

## 11. 広域地図でも局所を読める

PersonalMapは複数sessionや長距離移動から育つため、全体fitだけでは徒歩・建物周辺・発見地点が数pxへ潰れることがある。

- Reviewは最初に全体像を表示する
- Reviewでは拡大・縮小・移動と全体fitへの復帰を提供する
- 交通機関や遠距離区間をraw evidenceから削除して見かけの縮尺を合わせない
- 拡大はrenderer-only stateとし、PersonalMap bounds、segment、marker、accepted/rejectedを変更しない
- 高倍率でもmarker、開始・終了point、線幅を操作不能な大きさへ拡大しない
- ボタン操作と倍率表示を用意し、pinchだけへ依存しない
- 記録中live previewはPassive-firstを優先し、既定では閲覧操作を増やさない

## 主要画面

### Home

- 大きな `新しい地図を探索する`
- 最近更新したPersonalMap
- PersonalMapごとの探索回数と更新時刻
- 既存地図ではなく自分の探索サムネイル
- active sessionがあるPersonalMapは記録中として復帰可能

### 記録中

- `記録中`、経過時間、記録状態
- `スマホはしまって大丈夫です`
- `発見を記録`
- `探索を終了`
- 地図を常時表示しない

### 発見

- 少数の大きなカテゴリ
- 任意メモ
- 現在位置が取れない場合も時刻付きで保存し、後で接続可能にする

### PersonalMapレビュー

- 白紙キャンバス上の複数track segments
- 初期表示はPersonalMap全体fit
- 最大32倍の局所拡大、pan、倍率表示、全体fitへの復帰
- 各sessionの開始・終了
- 発見
- 合計距離、探索回数、時間
- raw / accepted / rejectedサンプル
- 記録ギャップと精度
- `この地図の続きを探索`
- 現providerで安全に座標統合できない場合は継続を無効化し、理由を示す
