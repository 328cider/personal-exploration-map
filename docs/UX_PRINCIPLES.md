# UI / UX原則

## 1. 現実が主画面

探索中に画面を見続ける設計は失敗とみなす。開始後は「スマホはしまって大丈夫」と明示し、必要時以外の操作を求めない。

### 必須フロー

```text
ホーム → 探索開始 → ポケット → 必要時だけ発見 → 探索終了 → レビュー
```

## 2. 一回の探索で成果を出す

「同じ場所を数回通ると道になる」は採用しない。初回の受理済みサンプルから即座に経路を作る。再訪は精度、接続、探索範囲を改善する材料にする。

## 3. モードを場所カテゴリで分けない

「山」「キャンプ」「街」「建物」の選択を開始前に要求しない。ユーザーに必要なのは `探索を始める` だけで、内部の位置プロバイダーや精度表示が環境に応じて変わる。

## 4. 権限は段階的に説明する

起動直後に位置権限を連続要求しない。

1. ユーザーが探索開始を選ぶ
2. 利用中の位置権限の理由を説明して要求
3. 「ポケットに入れて画面を消しても記録する」ためにバックグラウンド権限が必要だと説明
4. 拒否された場合は、動作制限を具体的に表示する

権限拒否をエラー扱いだけにせず、前面記録・設定を開く・中止の選択肢を示す。

## 5. 発見入力は10秒以内を目標にする

通常の記録は以下の2段階までにする。

```text
発見を記録 → 種類を1タップ → 保存
```

任意で短いメモを追加できる。写真を必須にしない。マーカー候補は少数に保ち、ユーザー定義は後から追加する。

初期候補:

- 気になる
- 入口 / 出口
- 分岐 / 接続
- 階段 / 高低差
- 危険 / 通れない
- メモ

## 6. 不確実性を地図の文法にする

誤差を隠して正確そうな線を描かない。

- 高確度: 実線・高い不透明度
- 低確度: 薄い線、幅、または警告
- 記録欠落: ギャップとして表示
- 手動入力: 観測方法を区別
- 推定構造: 事実レイヤーと分離

ユーザーが「地図が間違っている」のか「測位が不確か」なのかを判断できるようにする。

## 7. 終了忘れと中断から回復する

- Androidでは継続中通知から探索画面へ戻れる
- アプリ再起動時にactive sessionを検出する
- 長時間静止時は通知で確認するが、自動終了で記録を失わない
- OSにより記録が止まった場合は、終了レビューで欠落を表示する

## 8. 安全を損なわない

- 歩行中の画面注視を促さない
- 音や振動は最小限
- 危険な場所への立ち入りや探索率競争を促進しない
- 地図は救助・測量・安全保証用途ではないことを明示する

## 9. ゲームは任意で無効化できる

Fog、探索率、実績、収集物を使わなくても、地図アプリとして完成していること。ゲームのために記録開始や発見入力が複雑にならないこと。

## 主要画面

### ホーム

- 最近の探索地図
- 大きな `探索を始める`
- 既存地図ではなく自分の探索サムネイル

### 記録中

- `記録中`、経過時間、記録状態
- `スマホはしまって大丈夫です`
- `発見を記録`
- `探索を終了`
- 地図を常時表示しない

### 発見

- 少数の大きなカテゴリ
- 任意メモ
- 現在位置が取れない場合も時刻付きで保存し、後で接続可能にする

### レビュー

- 白紙キャンバス上の経路
- 発見
- 距離、時間、受理 / 除外サンプル
- 記録ギャップと精度
- 次回の続きとして保存
